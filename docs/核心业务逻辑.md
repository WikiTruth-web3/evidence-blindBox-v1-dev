# Evidence Market 核心业务逻辑说明文档

本文档详细说明 Evidence Market 项目的核心智能合约业务逻辑，重点阐述 **BlindBox (资产)**、**Exchange (交易)** 和 **FundManager (资金)** 之间的交互与生命周期管理。

---

## 1. 核心概念与合约架构

项目基于 **Oasis Sapphire** 隐私公链构建，利用其隐私计算特性实现了“加密信息交易”的独特业务。

- **BlindBox.sol**: 核心资产合约。管理信息的存储（加密数据）、状态流转、定价与有效期。
- **Exchange.sol**: 交易逻辑合约。管理挂单（Sell/Auction）、购买（Buy/Bid）、退款（Refund）与订单完成（Complete）。
- **FundManager.sol**: 资金管理合约。处理多币种支付、手续费扣除与收益分配, 引入预言机价格系统。

---

## 2. BlindBox：盲盒 (核心资产)

BlindBox 是平台交易的基本单元，每个 Box 包含公开信息与加密机密信息。

### 2.1 数据结构

```solidity
struct PublicData {
    BoxStatus _status;
    uint256 _price;
    uint256 _deadline;
}

struct SecretData {
    bytes32 _minterId;
    bytes _encryptedData; // Encrypted data (private key)
    bytes32 _nonce;// Encrypted nonce, decryption required
}
```

- **公开数据 (Public Data)**:
  - `BoxStatus`: 当前状态 (如出售中、已支付、公示中等)。
  - `Price`: 当前价格。
  - `Deadline`: 保护期截止时间。在此时间之前，非 Minter 持有者无法转售。
- **机密数据 (Secret Data)** (仅特定权限可见):
  - `EncryptedData`: 使用 Sapphire 隐私公钥加密的内容。
  - `Nonce`: 解密所需的随机数。
  - `MinterId`: 原始铸造者的`UserId`。

### 2.2 状态生命周期 (BoxStatus Lifecycle)

Box 的生命周期是一次性单向的，不能进行二次出售，一旦公开就永久性的公开，一旦被加入黑名单则无法再被移除。
```solidity
enum BoxStatus {Storing, Selling, Auctioning, Paid, Delaying, Refunding,  Published, Blacklisted}

```

Box 的状态流转是业务的核心：

1.  **Storing (存储中)**: 初始状态，或者从市场下架后的闲置状态。只有在此状态下可以发起 `sell` 或 `auction`。
2.  **Selling (一口价出售中)**: 正在市场上以固定价格出售。
3.  **Auctioning (拍卖中)**: 正在市场上进行拍卖。
4.  **Paid (已支付/待交割)**: 买家已付款，等待确认或申请退款。
5.  **Delaying (延迟批露中)**: 交易完成，内容仅买家可见，买家需要支付延迟批露费来延缓Box公开的时间。
6.  **Refunding (退款仲裁中)**: 买家发起了退款申请，等待 Minter 或 DAO 处理。
7.  **Published (已公开)**: 信息被完全公开，任何人（包括未付费用户）均可查看解密内容。
8.  **Blacklisted (黑名单)**: 因违规被 DAO 封禁。

### 2.3 主要功能函数

```solidity
function getSecretData(uint256 boxId_) external view returns (bytes memory); // 以太坊本地版
// 或在 Sapphire 中：
function getSecretData(uint256 boxId_, bytes memory siweToken_) external view returns (bytes memory);

function extendDeadline(uint256 boxId_, uint256 time_) external;
function delay(uint256 boxId_) external;
```

1. **getSecretData**: 读取私密数据（privateKey），在 Sapphire 中需要 siwe 令牌验证当前用户。
   - `Storing/Selling/Auctioning`时，只有 minter 可以查看。
   - `Paid/Delaying`时，只有 buyer 可以查看。
   - `Refunding/Published`时，所有人均可查看。
   
   > [!IMPORTANT]
   > **博弈威慑设计**：只要买家发起退款（状态进入 `Refunding`），盲盒的机密数据就会直接公开（任何人均可读取）。这种设计旨在威慑买家，防止其利用退款机制恶意“白嫖”机密数据资产。

2. **extendDeadline**：延迟 deadline，
   - `Storing`，并且`now < box.deadline`(未到期)，只有 minter 有该权限。
3. **delay**：支付延期费用以延长披露截止日期，
   - `Delaying`，并且`now <= box.deadline - 30 days`(窗口期小于 30 天)，所有人都可以代为支付延期费用。

## 3. Exchange：交易引擎

Exchange 合约处理交易，并通过严格的权限控制管理 Box 的流转。

- 主要功能函数

```solidity
function sell(uint256 boxId_,address acceptedToken_,uint256 price_) external;
function auction(uint256 boxId_,address acceptedToken_,uint256 price_) external;
function buy(uint256 boxId_) external;
function bid(uint256 boxId_) external;
function calcPayAmount(uint256 boxId_) external view returns (uint256);
function requestRefund(uint256 boxId_) external;
function agreeRefund(uint256 boxId_) external;

function cancelRefund(uint256 boxId_) external;
function completeOrder(uint256 boxId_) external;
```

### 3.1 出售 (Sell) 与 拍卖 (Auction)

这是项目中权限差异最明显的环节。

- **Minter (铸造者) 的特权**:

  - **随时出售**: 只要 Box 处于 `Storing` 状态，Minter 随时可以上架。
  - **自定义代币**: Minter 可以指定接收特定的 ERC20 代币（`acceptedToken`）。
  - **自定义价格**: Minter 可以随意设定新的价格。

- **其他用户**:
  - **必须等待 Deadline**: 只有当 `block.timestamp > deadline` (保护期结束) 后，才能发起出售/拍卖。
  - **不可更改代币**: 无法自定义接收代币，自动采用官方使用的结算代币。
  - **不可更改价格**: 代码逻辑中强制 `price_ = 0`，这意味着调用 `BlindBox.setPrice` 时会忽略更新，必须沿用 Box 原有的定价（或由其他逻辑控制）。

> **设计意图**: 这种机制保护了创作者 (Minter) 的初期利益，防止“黄牛”在信息发布的早期（保护期内）进行倒卖，同时确保信息的定价权在早期掌握在创作者手中。

### 3.2 购买与竞价

- **Buy (购买)**: 针对 `Selling` 状态。支付定价金额，状态立即变更为 `Paid`，并设置退款申请截止期 (`refundRequestDeadline`)。
- **Bid (竞价)**: 针对 `Auctioning` 状态。
  - 每次出价必须高于当前价格一定比例（如 10%）。
  - 出价成功会延长拍卖时间（防止狙击）。
  - 出价者会被设置为 buyer，（数据库会将其添加至 bidders 列表）
  - 不能重复出价，即当前的 buyer 不能出价（如果后续有其他人出价，就可以再次出价竞拍）。
  - 资金直接进入 FundManager 托管（orderAmount，）。
- **calcPayAmount（计算需要支付的资金）**：这是一个 View 类型的函数用于前端展示，通过该函数查看自己购买/竞拍这个Box需要支付多少资金。

### 3.3 售后流程 (Refund & Complete)

交易并非支付即结束，包含一个保护买家的“验货期”，申请退款也会有一个“审核期”：

1.  **Request Refund (申请退款)**: 买家在 `Paid` 状态, 若发现内容虚假，可申请退款。状态变为 `Refunding`。
2.  **Agree/Refuse Refund (处理退款)**: Minter 或 DAO 介入审核。

    - 同意退款 -> 钱退回买家，Box 变为 `Published` (既然是假的或有争议，往往意味着不再通过私密获利)。
    - 拒绝退款 -> 状态恢复为 `Delaying`，资金结算。
    - 如果`now > refundReviewPeriod`(超过审核期)，那么任何人都可以调用 agreeRefund。

## **注意**：拒绝退款功能在当前前端页面中不需要实现，因为它应该是一个 DAO 社区治理功能。

### 3.4 完成交易 (Complete)

任何执行`CompleteOrder`函数的用户都可以获得一份奖励`CompleterReward`, 包括Buyer也能获得，
并且在后续的DelayFee奖励分配中，也同样可以获得这部分奖励。


## 4. FundManager：资金流转

FundManager 负责所有“资金”的业务管理。

```solidity
function orderAmounts(uint256 boxId_, bytes32 userId_) external view returns (uint256);
function withdrawOrderAmounts(address token_, uint256[] calldata list_, address receiver_) external;
function withdrawRefundAmounts(address token_, uint256[] calldata list_, address receiver_) external;
function withdrawRewards(address token_, address receiver_) external;
```

### 4.1 订单金额（OrderAmount）

出售/拍卖的 Box 被购买/竞价时便会将资金存入 FundManager 合约 `_orderAmounts` 映射中。

- **refundPermit（退款许可）**: 当获得退款许可后，buyer 可以调用 `withdrawRefundAmounts` 函数取回自己的退款资金。
- **竞价失败**：`bidders.includes(user)`（属于竞拍者），并且 `user !== buyer`，则可以调用 `withdrawOrderAmounts` 函数取回自己的订单资金。

这两个函数都支持批量（boxId 数组）操作，在前端的 Profile 页面中，会展示列表进行复选框勾选。
**注意**：但是必须是同一个 token（box.acceptedToken）代币才能进行批量提款。

### 4.3 收益分配 (Allocation)

当订单完成 (`Complete Order`) 或拒绝退款时，资金会按比例分发：

1.  **Minter Reward**: 原始铸造者永远获得最大一部分版税。
2.  **Seller Reward**: 如果有卖家，则获得奖励。
3.  **Completer Reward**：如果有完成者，则获得奖励。
4.  **Service Fee**: 平台收取的手续费，转入 DAO Treasury。

---

## 5. 典型生命周期示例

1.  **铸造 (Mint)**: Minter 创建一个 BlindBox，设置价格 100 USDT，保护期 15 天。状态 `Storing`。
2.  **上架 (Sell)**: Minter 调用 `sell`。状态变为 `Selling`。
3.  **购买 (Buy)**: Buyer 支付 100 USDT。状态变为 `Paid`。资金暂存 FundManager。
4.  **确认 (Complete)**: Buyer 检查解密内容无误，调用 `completeOrder`。状态变为 `Delaying`。
    - 同时FundManager合约会将订单金额按比例分配给 Minter、Seller、Completer 和 DAO Treasury。
5.  **延迟批露期**: Buyer可以支付延迟批露费用，来延缓BlindBox的公开时间，如果停止支付，BlindBox则会在deadline 截止后变成公开状态。
